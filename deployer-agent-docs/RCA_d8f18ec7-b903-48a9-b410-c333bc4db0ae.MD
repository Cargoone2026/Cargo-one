## Overall assessment of the "Distance/Journey time —" symptom
Nothing in 24h of logs reproduces a backend failure on the normal quote flow: geo/details and geo/autocomplete are 200, Distance Matrix is 200, quote/estimate is 200 (422s are only legit over-capacity/over-volume), and no lat=0/missing-lat request ever arrived. So the "—" is **not** a logged 4xx/5xx or a Google error.

The two things the logs CANNOT see, which is where this likely lives:
1. **Response-body content of the 200s** — a 200 estimate can still carry `distance=null`/`duration=null` if the code treats a Google element whose per-element `status != OK` (or missing `duration_in_traffic`) as "no error" and returns null. That would render as "—" with a 200 in the log. Access logs can't show this.
2. **Client-side** — the iOS app may be timing out / dropping the response during the backend-saturation windows (the /health timeouts prove the backend stalls under load), or mis-parsing the distance field for city-level results.

## Recommended next steps (not applied — diagnosis only)
- **Code (E1):** add logging of the Distance Matrix per-element `status` and the `distance/duration` values the estimate endpoint returns, and explicitly handle element `status != OK` (ZERO_RESULTS/NOT_FOUND) rather than returning a silent null. Make the outbound Google call use an explicit httpx timeout and run non-blocking so a burst can't stall the event loop (which is what's timing out `/health`). Lower httpx log level so the API key isn't printed.
- **User (test_and_verify):** capture one real failing "—" Post-Job attempt with the exact `/api/geo/details` + `/api/quote/estimate` request/response (Charles/Proxyman on the TestFlight build) — that response body will show whether the backend returned null distance or the client dropped it.
- **Optional (performance):** the `/health` 503 timeouts only appeared under the heavy sweep on tier_1 (250m/500m CPU). Not a confirmed cause of "—" and no OOM occurred, so no forced tier change — but if real concurrent TestFlight load grows, consider the non-blocking fix above first, then tier if needed.
